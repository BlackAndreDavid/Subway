# 经营窗口

只和到店顾客交易，没有系统商品清单或补货。开店仍消耗一天；同一轮整理、买卖不额外消耗天数。每日顾客上限为 `ceil(站点游戏客流÷20)`，最低2人、最高10人。例如邮电新村4人、四平路6人、人民广场10人。成交后顾客继续停留，点“送客”才推进接待人数；最后一位离场后停止生成顾客，重绘界面不能刷新额度。

顾客按类别收购或出售，水、电、食物、药物、主动道具、模块各为一类；收购还包含材料、家具。收购时从下方仓库拖入同类商品，出售时从右侧顾客货物格拖入交易格，然后点“确认交易”。买卖共用中央8列×4行交易区，可摆放多件实物，一次确认整批转移；拖拽暂存或清空都不改变物品归属，错误类别不能放入。顾客有3–5件有限实物库存，没有无限补货。

每位顾客初始预算由日期、站点和序号确定，基础35–110水晶乘站点价格系数。玩家卖给顾客时，顾客预算减少、玩家水晶增加；玩家向顾客购买时相反。同一顾客可多次交易。价格超过付款方预算时显示“买不起”，确认按钮禁用，模型同样拒绝交易。保存失败整体回滚，旧交易版本和仓库位置已变化的拖拽不能重复结算。预算、库存、交易版本保存在存档中。

接客窗口高度由原来的约610像素减为285像素，立绘仍以原来的500像素身高绘制，仅裁切可见范围，不随窗口缩放。0.8秒走近、0.65秒离场的大小/不透明度/明暗过渡保留。仓库直接显示在下方，支持格子拖拽、旋转、查看和资源入库，不再用按钮打开。

`scenes/shop/shop.tscn` 管理交互，`scenes/shop/customer_window.tscn` 封装人物呈现，`scripts/shop_rules.gd` 管理客流折算、类别需求和有限库存。四位顾客的提示词、双候选、源图哈希与共享32色像素素材保持原样。

`tests/shop_checks.gd` 覆盖每日限额、实际鼠标拖拽、类别选择、双向预算、买不起、剩余库存、保存/读取、重复交易和裁切尺寸；原生测试 `tests/native_shop_checks.gd` 已纳入CI。截图 `shop.png`、`shop_budget.png`、`shop_customer_0..3.png` 及远处/离场版本可复查。

仓库、顾客货物、交易区统一48像素格子，拖拽预览、占格和落点使用同一坐标单位。交易区支持真实形状摆放、旋转、重排；同一来源副本只能预留一次，拖回库存可取消单件，清空取消全部。金额随增减自动合计。预算/水晶检查针对整批总价，确认后倒序移除源索引、一次转移总金额、一次保存；失败不部分成交。`shop_cart.gd`封装交易区摆放与预留，`Game.customer_quote/accept_customer`独立校验几何、重复来源、交易版本和总价。

货币现在为[水晶](currency.md)，电量仅用于补给与通行。批量售出、批量购入及水晶掉落原生截图为`shop_batch_sell.png`、`shop_batch_buy.png`、`crystal_drop.png`；`tests/shop_basket_checks.gd`及`tests/crystal_checks.gd`已纳入普通和原生回归。
